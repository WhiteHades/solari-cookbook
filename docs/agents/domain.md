# Domain docs

Read `CONTEXT.md` before naming domain concepts in code, tests, tickets, or documentation. Use its terms rather than near-synonyms.

Read ADRs under `docs/adr/` that touch the work being changed. Surface conflicts instead of silently replacing a recorded decision.

`CONTEXT.md` is a glossary only. Product behavior belongs in the specification, tickets, tests, and product README. Hard-to-reverse tradeoffs belong in ADRs.
